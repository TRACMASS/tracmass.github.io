Killing trajectories (UNDER CONSTRUCTION - spelling and grammar check)

Introduction

In TRACMASS, there are 4 types of terminating or "killing" trajectories. Here we will breifly present how to set them up. In general, trajectory killing is done by file kill_zones.F90, but in most cases, no modifications need to be made there. The only exception is when exitType=4, in which case the user needs to write FORTRAN code in kill_zones.F90 that will terminate trajectories in some locations. The file itself is located in the project's folder, which you can read more about here.

Various exit types (exitType)

exitType=1: BOX

This trajectory killer is the simplest to implement, as it requires only the coordinates of the box that would reperesent the killzone.

Here is shown an example of how to set up kill zones with exitType=1, which is a regular box. Similarly as with tracer set up, a maximum of 10 killzone boxes can be set with this option. Here we have set up 2 boxes, first acting as a line and the second as a rectangular box. The first box has the dimensions from 200-th to 300-th index in the west-east direction and is set to 150-th index in the north-south direction. Looking form a bird eye view that would be a horizontal line across the grid. The second killzone box is truly a box with size from 50-th to 250-th index in west-east direction and from 350-th to 450-th index in the north-south direction. Once the box line is crossed, the trajectory is terminated; it does not matter from which side the trajectory crosses.

Note:
The kill zone box is implemented in all model levels, it is not possible to specify in which heights the termination should occur.

exitType=2: TRACER VALUE

This exit type kills trajectories once a maximum or minimum value has been reached by a tracer that is measured along the trajectory. In this example we will implement two tracers that will be used to terminate the trajectories - temperature and salinity. First, it is necessary to enable tracers, otherwise, when running TRACMASS an error will appear saying that 'Fortran runtime error: Index '1' of dimension 1 of array 'tracervalue' above upper bound of 0' which means that there are no tracers available fro TRACMASS. Thus, the tracers need to be set up as usual, some of the values mgight be different for your case, such as the tracervarname.

Next, the kill zones need to be set up, here we enable both temperature and salinity values of the tracers to kill trajectories. In this case, we set up so that the temperature of tracers does not exceed 25 degrees; this is done by setting the variable maxormin=1. To set up a minimum value that tracers need to be, maxormin must be set to -1, as shown with salinity - it has been set to have a minimum value of 35 PSU. If any of the trajectories reach a value that is lower than 35 PSU, it will be terminated.

Note:

exitType=3: BOX & TRACER VALUE

In this case, a kill zone is defined with a geographic location and the tracer values. For this, the namelist code presented in the other two sections needs to be used. It is essentially the same, but with a possability to have more restraining and precise kill zone definitions.

Maximum Trajectory runtime

It is also possible to set a maximum time for trajectories to run in namelist with timax. This sets the maximum trajectory runtime in days and it will terminate the simulation itself, once all the trajectories are terminated. The simulation will be terminated, even if in the future timesteps more trajectories will be added.

⚠ Warning:
If the simulation runs out of trajectories, even though more trajectories will be added in the future timesteps, the simulation will terminate!
